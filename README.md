# Педагог ДО

Платформа поддержки обучения для педагогов дополнительного образования. Версия 0.0.4 реализует кабинет для подачи заявок на программы методической поддержки.

История смены предметной области и соответствие функций предыдущим работам описаны в [LAB4-CONTEXT.md](LAB4-CONTEXT.md).

## Запуск

Репозиторий: https://github.com/ksushka2/APAHOVA_MispisitLabs

Ветка: lab4

Pull Request: https://github.com/ksushka2/APAHOVA_MispisitLabs/pull/4

Образ: ksushkaap/mispisit-lab1:0.0.4

```bash
git clone -b lab4 https://github.com/ksushka2/APAHOVA_MispisitLabs
cd APAHOVA_MispisitLabs
docker compose up -d
```

Адрес кабинета — http://localhost:8080. Версия 0.0.4 видна в шапке каждого экрана.

## Локальная проверка на этом компьютере

Запустите Docker Desktop и выполните в существующем репозитории:

```powershell
Set-Location -LiteralPath 'C:\Users\Ксюня\Documents\GitHub\APAHOVA_MispisitLabs'
docker compose up -d --pull never
```

Команда использует локальные образы `ksushkaap/mispisit-lab1:0.0.4` и `postgres:18`. Она запускает приложение на прежнем томе `dbdata`, если он уже есть. При первом запуске кабинета на этом томе реестр педагогов пуст. Если Docker сообщит, что образ отсутствует, после публикации тега выполните обычный запуск из раздела выше.

По окончании выполните `docker compose stop`. Том и запись сохранятся для следующего запуска.

## Сценарий проверки

| Экран | Адрес | Что проверить |
| --- | --- | --- |
| Главная | `/` | Название платформы, версия, переходы к реестру, форме и проверке отказа |
| Реестр | `/requests/` | На первом запуске без заявок видна кнопка «Создать первую заявку» |
| Форма | `/requests/new/` | Введите учебные ФИО, организацию, почту и стаж. Выберите программу |
| Карточка | `/requests/<id>/` | После отправки видны номер и сведения заявки. По кнопке «К реестру заявок» видна новая строка |
| Отказ | `/access-denied/` | Доступны шаги проверки. После запрещённого действия здесь видна фактическая причина |

1. Откройте «Заявки». В новой базе видно сообщение «Заявок пока нет».
2. Откройте «Новую заявку». Для примера введите «Мария Орлова», «Центр творчества Вектор», `m.orlova@example.com`, стаж 4 года. Выберите «Наставничество педагогов» и отправьте. В карточке появится номер, а по возврате к реестру видна запись с тем же номером.
3. Заполните форму снова. С той же программой укажите 1 год стажа. Сервер перенаправит на экран «Действие не выполнено» с объяснением и вернёт HTTP 422. Число записей останется прежним.
4. Для второго сценария откройте реестр в приватном окне и нажмите «Открыть» у сохранённой заявки. Сайт покажет отказ HTTP 403. Реестр содержит номер, программу и дату. Контактные данные видны в карточке браузера, подавшего заявку.
5. После `docker compose restart app` обновите реестр. Запись хранится в PostgreSQL и остаётся доступной.

В Compose используются сервисы `app` и `db`, имя проекта `mispisit-apahova` и том `dbdata` из ЛР №3. Django ждёт готовности PostgreSQL по `service_healthy` и применяет миграции. При обновлении тома ЛР №3 сохраняются таблицы курсов и заявок IT-школы. Кабинет использует собственные таблицы в той же базе.

## Сборка и публикация образа

```bash
docker buildx build --platform linux/amd64,linux/arm64 -t ksushkaap/mispisit-lab1:0.0.4 --push .
docker buildx imagetools inspect ksushkaap/mispisit-lab1:0.0.4
```

Проверьте в манифесте платформы `linux/amd64` и `linux/arm64` и публичный доступ к тегу. После слияния PR оставьте ветку `lab4` на GitHub, чтобы команда клонирования оставалась рабочей.
