# IT-Школа — лабораторная работа №4

Информационная система детской IT-школы. Автор: Апахова Ксения, ИСТбд-41. Версия **0.0.4** продолжает тему лабораторных работ 1–3: родитель подаёт заявку на курс, сотрудник школы или родитель просматривает заявки, система проверяет возрастные ограничения и показывает отказ на отдельной странице.

## Что подготовлено

Простые страницы без декоративных иллюстраций, значков и рекламных слоганов. Пять экранов с общим меню: главная с направлениями обучения, список заявок, форма записи, карточка заявки и страница отказа. Светло-голубой фон `#E7F3FC`, бургунди `#800030` для кнопок, ссылок и акцентов. Версия 0.0.4 видна на каждом экране. Пустой список оформлен и содержит переход к первой заявке. Ошибки заполнения показываются рядом с полями без потери введённых значений.

Исходный код подготовлен локально. Публикация в GitHub и Docker Hub выполняется автором самостоятельно. До публикации обновлённого образа команда из раздела «Запуск» может скачать прежнюю заготовку 0.0.4. Для проверки подготовленных файлов используйте локальную сборку ниже.

## Локальная проверка подготовленных файлов

Из корня проекта при запущенном Docker Desktop:

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --build
```

Откройте [http://localhost:8080](http://localhost:8080). Дополнительный файл задаёт сборку исходников и отдельное локальное имя `mispisit-it-school-local:0.0.4`. Основной файл для сдачи по-прежнему использует опубликованный образ и не содержит `build`.

Для остановки с сохранением базы:

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml stop
```

Приложение применяет миграции к существующему тому `dbdata`. Справочник и заявки IT-школы из работы №3 остаются в тех же таблицах. Предыдущие таблицы заготовки «Педагог ДО» также сохраняются; этот кабинет не используется интерфейсом данной работы. Команды удаления томов для запуска и обновления не нужны.

## Решение об интерфейсе

| Кто работает с данными | Кто клиент | Где живёт интерфейс версии | Чем собран вид | Что отложено |
| --- | --- | --- | --- | --- |
| Сотрудник детской IT-школы просматривает заявки; родитель вводит сведения | Родитель ребёнка | Общие страницы внутри Django-приложения, сервис `app` | Django Templates, локальный Bootstrap 5.3.8 и собственный CSS | Отдельный кабинет сотрудника, учётные записи и мобильное приложение |

Рассмотрены общий интерфейс в существующем приложении, отдельная административная панель и отдельный клиентский фронтенд. Выбран первый вариант: для трёх функций достаточно серверных страниц, уже принятых в работе №2. Второй сервис с React или Vue не требуется. Платформа Python 3.11 / Django 4.2.16 из работы №1 и PostgreSQL 18 из работы №3 сохранены.

Вместо служебных страниц работ 1–3 собран общий адаптивный макет: меню, таблица курсов, форма, состояния списка и экран отказа. Отдельные макеты третьего курса в эту версию не переносились: новый макет объединяет пять уже реализованных экранов и позволяет пройти три сценария без ручного ввода адресов. Предметная область остаётся прежней — детская IT-школа.

## Функции и экраны

| Экран | Адрес | Действие |
| --- | --- | --- |
| Главная | `/` | Выбор направления из базы и переход к записи |
| Заявки | `/requests/` | Чтение сохранённых заявок; до первой записи — завершённое пустое состояние |
| Запись на курс | `/requests/new/` | Создание записи `StudentRequest` в PostgreSQL |
| Карточка | `/requests/<id>/` | Курс, данные ребёнка и родителя, номер заявки |
| Отказ | `/access-denied/` | Инструкция проверки или фактическая причина отказа |

Сценарий несовпадения телефона из работ №2–3 сохранён как учебная проверка: в карточке есть поле телефона для проверки, неправильный номер вызывает HTTP 403. Общий интерфейс не реализует вход в учётную запись; эта проверка не является полноценной авторизацией. При неподходящем возрасте открывается отказ HTTP 422; отсутствующая заявка даёт HTTP 404. Неверно заполненная форма возвращает HTTP 400 и показывает ошибки у полей.

## Сценарий проверки

1. В новой базе откройте «Заявки» и зафиксируйте пустой список. На существующем томе заявки работы №3 уже могут присутствовать — очищать его не требуется. Пустое состояние для отчёта снимайте на отдельной учебной базе.
2. Нажмите «Новая заявка». Введите учебные данные: ребёнок — «Анна Смирнова», возраст — 8, родитель — «Мария Смирнова», телефон — `+7 (900) 123-45-67`, почта — `parent@example.com`. Выберите «Scratch для начинающих» (7–9 лет).
3. Отправьте форму. Откроется карточка с номером `REQ-…`. Перейдите к списку: там должна быть строка с тем же номером и курсом.
4. Повторите ввод, указав для Scratch возраст 12 лет. Откроется отдельный экран «Возраст не подходит для курса» с кодом HTTP 422. Число заявок не увеличится.
5. Откройте существующую карточку и внизу введите другой телефон, например `+7 (911) 111-11-11`. Получите отдельную страницу «Чужая заявка», HTTP 403.
6. Оставьте обязательное поле пустым или укажите некорректную почту. Форма покажет ошибки; новая запись не создаётся.
7. Выполните `docker compose restart app` (при локальной сборке укажите оба compose-файла, как выше), затем обновите список. Запись должна остаться в PostgreSQL.

## Хранение и Docker Compose

Сохранены имя проекта `mispisit-apahova`, сервисы `app` и `db`, образ базы `postgres:18`, том `dbdata`, `PGDATA=/var/lib/postgresql/data/pgdata` и монтирование `dbdata:/var/lib/postgresql/data`. Порт базы наружу не опубликован. Приложение получает строку подключения через окружение и ждёт успешного `healthcheck` базы. Основной `docker-compose.yml` не содержит `build` и использует тег `0.0.4`.

Рабочие таблицы — `core_course` и `core_studentrequest`. Миграция `0003_seed_it_school_courses` заполняет курсы только в пустом справочнике. Она не удаляет и не изменяет существующие курсы или заявки. Модели и миграция предыдущей заготовки сохранены для совместимости с уже созданной базой.

## Самостоятельная публикация

После проверки исходников опубликуйте новый образ, сохранив теги 0.0.1–0.0.3:

```bash
docker buildx build --platform linux/amd64,linux/arm64 -t ksushkaap/mispisit-lab1:0.0.4 --push .
docker buildx imagetools inspect ksushkaap/mispisit-lab1:0.0.4
```

Убедитесь, что доступны `linux/amd64` и `linux/arm64`, а образ скачивается без входа. Затем самостоятельно добавьте файлы в ветку `lab4` и оформите Pull Request в основную ветку. После слияния оставьте `lab4`, чтобы преподаватель смог клонировать её.
