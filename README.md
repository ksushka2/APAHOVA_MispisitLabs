# IT-Школа — лабораторная работа №5

Информационная система детской IT-школы. Апахова Ксения, ИСТбд-41. Версия 0.0.5.

После создания заявки система сохраняет внутреннее уведомление. На странице «Уведомления» видны номер заявки, курс, время, статус «Новое» и ссылка на карточку заявки.

## Проверка на моём компьютере до публикации

Файлы пятой лабы находятся в ветке `lab5` этого репозитория. Для проверки используется отдельный Compose-проект `mispisit-apahova-lab5-local`, собственный том базы и порт 8085. Такой запуск не заменяет приложение четвёртой лабы на порту 8080 и не обращается к её базе.

Запустите Docker Desktop, затем выполните в CMD:

```cmd
cd /d "C:\Users\Ксюня\Documents\GitHub\APAHOVA_MispisitLabs"
docker compose -f docker-compose.local.yml up -d --build
```

Откройте [http://localhost:8085](http://localhost:8085). На странице должна быть версия **0.0.5**.

Локальная сборка получает отдельное имя `mispisit-it-school-local:0.0.5`. Образ `ksushkaap/mispisit-lab1:0.0.4` при этом не скачивается, не пересобирается и не перезаписывается.

Остановить только эту проверочную версию:

```cmd
docker compose -f docker-compose.local.yml stop
```

Повторный запуск после изменения файлов:

```cmd
docker compose -f docker-compose.local.yml up -d --build
```

Сохранённые заявки и уведомления остаются в отдельном томе `mispisit-apahova-lab5-local_dbdata`.

## Запуск

Этот раздел предназначен для запуска скачанного образа после публикации ветки `lab5` и образа `0.0.5`. Подготовленные локальные файлы сами по себе их не публикуют.

Репозиторий: [APAHOVA_MispisitLabs](https://github.com/ksushka2/APAHOVA_MispisitLabs)

Ветка: `lab5`

Pull Request: вставить фактическую ссылку после создания Pull Request из `lab5` в основную ветку.

Образ: `ksushkaap/mispisit-lab1:0.0.5`

Страница образа: [Docker Hub](https://hub.docker.com/r/ksushkaap/mispisit-lab1/tags?name=0.0.5)

Нужны Git и Docker с поддержкой Compose. На Windows запустите Docker Desktop и дождитесь его готовности. Порт 8080 должен быть свободен. На компьютере с запущенной четвёртой лабой для отдельной проверки используйте предыдущий раздел с портом 8085.

При первом запуске выполните по одной команде в строке:

```cmd
git clone -b lab5 https://github.com/ksushka2/APAHOVA_MispisitLabs APAHOVA_MispisitLabs-lab5
cd APAHOVA_MispisitLabs-lab5
docker compose pull
docker compose up -d
```

`docker compose pull` скачивает образ приложения с тегом `0.0.5` и PostgreSQL. `docker compose up -d` запускает приложение и базу. На компьютере преподавателя ничего не собирается. Отдельная команда `docker run` не нужна.

Откройте [http://localhost:8080](http://localhost:8080). На страницах отображается **Версия 0.0.5**.

Для повторного запуска из этой же папки:

```cmd
docker compose pull
docker compose up -d
```

Проверка состояния и журнала:

```cmd
docker compose ps
docker compose logs --tail=50 app
```

Остановка с сохранением записей:

```cmd
docker compose stop
```

Основной `docker-compose.yml` сохраняет имя проекта `mispisit-apahova`, сервисы `app` и `db`, настройки подключения и том `dbdata` из четвёртой лабы. В образе приложения изменён только тег на `0.0.5`. Этот основной вариант рассчитан на запуск преподавателем либо на последовательное обновление версии; для одновременной работы с четвёртой лабой предусмотрен отдельный локальный файл выше.

## Как проверить уведомление

1. Откройте «Уведомления». На новой базе отображается «Уведомлений пока нет».
2. Перейдите в «Новая заявка» и заполните форму. Например, выберите «Scratch для начинающих» и возраст 8 лет.
3. Сохраните заявку. Откроется её карточка с номером `REQ-…`.
4. Откройте «Уведомления». Появится сообщение «Поступила заявка REQ-… на курс «Scratch для начинающих»», время и статус «Новое».
5. Нажмите «Открыть заявку»: откроется карточка именно этой записи.
6. Обновите страницу или перезапустите приложение. Сообщение сохранится.
7. Отправьте заявку на Scratch с возрастом 12 лет. Откроется отказ; новая заявка и новое уведомление не появятся. Ошибки заполнения формы также не создают записей.

Просмотр списка или переход в карточку не меняет статус уведомления. В этой версии реализовано сохранение нового сообщения; отдельного действия «Прочитано» нет.

Уведомления появляются для заявок, созданных через форму версии 0.0.5. Для старых заявок сообщения задним числом не создаются.

## Выбранное событие

| Действие из трёх функций | Кому нужно узнать | Выбранный вариант | Что видно на экране | Что отложено |
| --- | --- | --- | --- | --- |
| Создание заявки на обучение | Сотруднику IT-школы, который принимает заявки | Внутреннее уведомление | Сообщение с номером заявки и курсом, время, статус и переход в карточку | Экран наблюдения за системой |

Внутренний канал нужен сотруднику для просмотра новых заявок в приложении. Отдельные страницы администратора, учётные записи и роли для этого задания не добавлены. Email, SMS и мессенджеры здесь не подключаются.

Вторым вариантом рассматривалось наблюдение за системой. Для выбранного процесса важнее показать сотруднику конкретную новую заявку. Проверка доступности и сбор метрик не решают эту задачу. При появлении настоящих пользователей пригодятся проверка доступности и журнал ошибок; в этой работе отдельные сервисы наблюдения не разворачиваются.

## Новая сущность

Уведомление хранится в отдельной таблице PostgreSQL `core_notification`. Это новая сущность, которой не было в третьей и четвёртой работах.

| Поле | Назначение |
| --- | --- |
| `id` | Идентификатор уведомления |
| `request_id` | Внешний ключ на конкретную заявку `core_studentrequest` |
| `event_type` | Тип события `request_created` — создана заявка |
| `message` | Сохранённый текст с номером заявки и названием курса |
| `created_at` | Дата и время создания события |
| `status` | Статус `new`, на странице — «Новое» |

Заявка и уведомление сохраняются в одной транзакции. Если сохранить уведомление не удалось, заявка также не сохраняется. Ограничение на пару `request_id` и `event_type` не позволяет записать два одинаковых события создания для одной заявки.

При запуске контейнера выполняются уже существующие команды подготовки таблиц прошлых работ, затем команда `python manage.py init_notifications`. Она создаёт таблицу уведомлений, только если её ещё нет. Существующие таблицы и записи не очищаются.

Новый инструмент миграций и новые файлы миграций для пятой лабы не добавлены. У модели `Notification` задано `managed = False`: её таблицей управляет команда начальной подготовки через Django SchemaEditor. Изменение заполненной структуры базы отложено до следующей работы.

## Что осталось от четвёртой лабы

Сохраняются курсы, форма заявки, список заявок, карточка и отказ при неподходящем возрасте. Проверка несовпадения телефона в карточке также остаётся. К общему меню добавлен пункт «Уведомления».

Используются Python 3.11, Django 4.2.16 и PostgreSQL 18. Страницы собраны на Django Templates с локальным Bootstrap и собственным CSS: светло-голубой фон, бургунди-кнопки и ссылки. Новые изображения и внешние библиотеки не добавлены.

## Публикация автором

Эти команды выполняет автор, когда решит опубликовать проверенную версию. Они приведены как инструкция и не являются частью запуска преподавателем.

Из папки пятой лабы:

```cmd
docker login -u ksushkaap
docker buildx build --platform linux/amd64 -t ksushkaap/mispisit-lab1:0.0.5 --push .
```

Публикуется только тег `0.0.5`. Теги `0.0.1`, `0.0.2`, `0.0.3` и `0.0.4` не перезаписываются.

Затем разместите файлы в ветке `lab5`, откройте Pull Request в основную ветку и вставьте его реальную ссылку в раздел «Запуск» и в отчёт. Ветку `lab5` после слияния сохраните.
