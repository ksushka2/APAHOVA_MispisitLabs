# IT-Школа — лабораторная работа №5

Апахова Ксения, ИСТбд-41. Информационная система детской IT-школы. Версия 0.0.5, вариант с очередью уведомлений, отдельным worker и Mailpit.

После создания заявки приложение сохраняет уведомление со статусом «Новое». Worker читает очередь из PostgreSQL, отправляет письмо сотруднику в Mailpit и меняет статус на «Отправлено». На странице «Уведомления» остаются номер заявки, курс, время, статус и ссылка на карточку.

Ветка для сдачи — `lab5`, как указано в методичке. Worker и Mailpit разрешены в этой лабораторной как дополнительный вариант. Новая ветка `5.1` не требуется.

## Сценарий демонстрации

1. Откройте «Уведомления». На новой базе отображается «Уведомлений пока нет».
2. Создайте заявку, например на Scratch для ребёнка 8 лет. Откроется карточка с номером REQ-….
3. Откройте «Уведомления». Появится сообщение с номером и курсом. Вначале оно имеет статус «Новое», после обработки worker — «Отправлено». Пока есть новые записи, страница обновляется раз в 5 секунд.
4. Откройте «Письма сотруднику» или Mailpit по адресу выше. Найдите письмо с тем же номером заявки. В письме есть курс и ссылка на карточку.
5. Перезапустите проект: заявка, статус и письмо сохранятся в томах. Уже отправленные уведомления worker повторно не выбирает.
6. Отправьте заявку с неподходящим возрастом либо ошибкой формы. Новая заявка, уведомление и письмо не создаются.

Worker проверяет очередь раз в 3 секунды. Поэтому на быстрой проверке сразу может быть виден статус «Отправлено». Для показа обеих стадий можно временно остановить только worker:

```cmd
docker compose stop worker
```

Создайте заявку и покажите статус «Новое», затем запустите обработчик:

```cmd
docker compose start worker
```

Через несколько секунд страница покажет «Отправлено», а в Mailpit появится письмо. При локальной проверке к этим командам добавляется `-f docker-compose.local.yml`, как в первом разделе.

## Выбор события и канала

| Действие | Кому нужно узнать | Выбранный вариант | Что видно | Что отложено |
| --- | --- | --- | --- | --- |
| Создание заявки на обучение | Сотруднику IT-школы | Внутреннее уведомление и email через worker | Сообщение с номером и курсом, смена статуса, письмо в Mailpit | Экран наблюдения за системой |

Сотруднику нужно узнавать о новых заявках и переходить в их карточки. Внутренний список сохраняет историю, а email показывает доставку сообщения отдельным обработчиком. В учебной версии письма принимает Mailpit; отправка во внешние почтовые ящики не настроена.

Вторым вариантом рассматривалось наблюдение за системой. Оно показывает доступность и ошибки сервиса, но выбранному процессу сейчас нужно сообщение о конкретной заявке. При появлении настоящих пользователей пригодятся проверка доступности и журнал ошибок. Отдельные сервисы метрик и наблюдения в этой работе не разворачиваются.

Авторизация, роли, отдельный кабинет администратора и брокер сообщений не добавлялись. Форма, список, карточка и ошибочные сценарии предыдущих работ сохранены. Оформление прежнее: Django Templates, локальный Bootstrap, голубой фон и бургунди-элементы.

## Таблица уведомлений и очередь

Используется новая для пятой лабы таблица `core_notification`. В работах 3–4 её не было.

| Поле | Назначение |
| --- | --- |
| `id` | Идентификатор события |
| `request_id` | Внешний ключ на конкретную заявку |
| `event_type` | `request_created` — создана заявка |
| `message` | Сохранённый текст с номером заявки и курсом |
| `created_at` | Время создания уведомления |
| `status` | `new` — «Новое», `sent` — «Отправлено» |

Новые поля для worker не нужны: оба статуса помещаются в уже существующее строковое поле. Прежние заявки и уведомления не очищаются. Существующие уведомления со статусом `new` также будут обработаны после запуска worker.

Заявка и новая запись очереди сохраняются одной транзакцией. При запуске `app` выполняется прежняя подготовка таблиц и команда `init_notifications`: она создаёт таблицу, если её ещё нет. Новые миграции и инструмент миграций не добавлены.

Worker использует блокировку выбранной строки PostgreSQL через `select_for_update(skip_locked=True)`, чтобы два одновременно запущенных обработчика не взяли одну запись. После принятия письма SMTP-сервером статус меняется на `sent`. При ошибке SMTP транзакция откатывается и сообщение остаётся новым; повтор выполняется после паузы.

Статус «Отправлено» означает, что Mailpit принял письмо. Он не означает, что сотрудник прочитал его. SMTP и PostgreSQL не образуют общую транзакцию: аварийное завершение между отправкой и фиксацией статуса может привести к повторному письму. Для учебной очереди используется повторная доставка; гарантия строго однократной отправки не заявляется.

## Сервисы и настройки

| Сервис | Назначение |
| --- | --- |
| `app` | Django, страницы и создание заявок, запись уведомления в очередь |
| `worker` | Тот же образ, команда `python manage.py process_notifications` |
| `db` | PostgreSQL 18, заявки и очередь в томе `dbdata` |
| `mailpit` | `axllent/mailpit:v1.33.0`, приём и просмотр писем, том `maildata` |

Worker запускается после готовности приложения и его таблиц. Адрес SMTP передаётся через `SMTP_HOST=mailpit`, порт — `SMTP_PORT=1025`. Используется встроенная отправка Django `EmailMessage`; дополнительные Python-библиотеки не требуются.

Получатель по умолчанию — тестовый адрес сотрудника `staff@it-school.test`, отправитель — `noreply@it-school.test`. Настройки можно задать переменными `NOTIFICATION_RECIPIENT` и `PUBLIC_BASE_URL`. Для основного запуска ссылка в письме ведёт на localhost:8080; локальная проверка настраивает localhost:8085. ФИО и контакты родителя в письмо не включаются.

## Основные изменения

- `core/notifications.py`: отправка одного сообщения и фиксация статуса.
- `core/management/commands/process_notifications.py`: цикл worker, паузы и повторные попытки.
- `core/models.py`: добавлен статус `sent`.
- `it_school/settings.py`: SMTP, тестовый получатель и адрес карточки.
- `core/views.py` и шаблон уведомлений: отображение статусов, ссылка на почту и обновление страницы.
- `docker-compose.yml`: app, db, worker и Mailpit без локальной сборки.
- `docker-compose.local.yml`: отдельная проверка со сборкой на портах 8085 и 8026.

В Gunicorn включены два потока обработки соединений. Это относится к новой локальной сборке версии 0.0.5.
